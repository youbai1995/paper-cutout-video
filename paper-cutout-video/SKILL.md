# 纸张剪纸拼贴解说视频

## 目标

把一个事实、过程、关系或故事，做成“纸张环境 + 动态解释层 + 剪纸主体”的可编辑视频。地图和路线只是可选场景类型，不是默认前提。保留真实来源和原始素材，只在派生工程中风格化。

## 硬规则

- 不伪造事实、时间、数据、地理结构、产品界面或实测结果。无法核实时标记为 `EXPLAINER`，不得暗示为真实证据。
- 不用生成式图片单独承担必须准确的地图、图表、界面或路线；准确结构使用可信数据、真实截图、SVG、GeoJSON 或人工描摹。
- 静态底板和动态覆盖层分开：背景、纸张区域、线条/路径、标签、剪纸主体、字幕和音频必须能独立编辑。
- 每 1.5–2.5 秒只引入一个主要信息变化。每个场景只保留一个主要视觉主体。
- 动画必须由 Remotion 帧驱动。不得依赖 CSS transition、CSS animation 或未与时间线同步的运行时动画。
- 原始音频、图片、地图、截图和录屏不覆盖；全部修改放入项目 `edit/`。
- 左右黑边、播放器提示和录屏 UI 属于捕获痕迹，不作为风格复刻。
- 未完成抽帧、转场、字幕、响度和闪帧检查时，只称为样片。

## 先选择交付层级

根据用户动词确定范围：

- “给方案、生产文档、镜头表”：只完成文档，不创建视频工程。
- “搭模板、做工程、做样片”：创建 Remotion 工程并完成低成本预览。
- “制作、生成视频、导出成片”：完成工程、渲染和全部质量门槛。
- “复刻参考视频”：先分析参考，再迁移镜头机制；不得复制其受版权保护的素材。

## 工作流

### 1. 建立项目骨架

在用户指定的项目目录运行：

```bash
python3 <skill-dir>/scripts/scaffold_project.py <project-dir> \
  --title "项目标题" --duration 30 --fps 30 --width 1920 --height 1080
```

脚本只新增缺失文件，不覆盖已存在内容。生成后持续更新 `edit/project.md`、`brief.md`、`script.md`、`shotlist.md`、`assets-manifest.md` 和 `motion-spec.json`。

### 2. 完成生产 brief

至少确定：

- 主题、一句话结论和目标观众；
- 需要证明的事实与来源；
- 目标时长、画幅、帧率和平台；
- 场景语法、纸张环境、动态解释层、剪纸主体、字幕和声音素材；
- 交付层级。

先选最适合内容的场景语法：

- `map-route`：地点、区域、航路、迁移、传播；
- `timeline-process`：历史进程、步骤、因果链；
- `relationship-board`：人物、组织、概念关系；
- `comparison`：前后变化、方案对比、版本演进；
- `product-story`：真实界面、功能过程与结果证明。

用户未给出非关键参数时，默认 1920×1080、30fps、16:9，并在 `brief.md` 记录假设。只有会改变事实或核心视觉方向的缺口才暂停询问。

### 3. 划定真实性边界

在素材清单中标注：

- `REAL LOCAL`：用户提供或本机实际生成/运行的素材；
- `OFFICIAL`：官方或可验证公开来源；
- `LICENSED`：具备明确使用许可的第三方素材；
- `GENERATED`：生成式素材，不作为事实证据；
- `EXPLAINER`：自制示意图、路径和关系动画；
- `PLACEHOLDER`：缺失素材，只能进入样片工作清单。

涉及事实核验或最新数据时浏览权威来源。涉及地图、图表或产品界面时，优先使用可信数据或真实截图。

### 4. 把口播与画面同时拆解

先写声音时间线，再写画面。为每句口播同时填写：开始/结束时间、主要视觉主体、素材来源、动画动作、字幕文本和音效。

优先使用以下通用叙事链：

```text
问题/语境建立 → 第一层变化 → 关系或方向形成
→ 主体/证据出现 → 结果成立 → 一句结论
```

地图路线可以用“地点 → 区域 → 路径 → 流向 → 主体 → 结论”；流程类可以用“问题 → 步骤卡片 → 连线 → 结果剪纸 → 结论”。每 1.5–2.5 秒只增加一个主要信息点。

需要详细视觉规格时完整阅读 [style-spec.md](references/style-spec.md)。

### 5. 准备分层素材

至少准备：

1. `background`：最终画幅尺寸以上的纸张环境或真实证据底板；
2. `paper-layers`：需要逐步揭示的纸片、区域、卡片或遮罩；
3. `lines-paths`：关系线、路线、时间线或方向标记；
4. `labels-icons`：标签、数据、解释图标和来源标记；
5. `cutouts`：透明主体 PNG/WebP，完整、不截肢、白边一致；
6. `captions`：Remotion `Caption[]` JSON；
7. `audio`：旁白、音乐和按时间点触发的音效。

背景可以生成或风格化，但事实性结构必须保留独立、可验证的来源。为彩色纸片叠加纸纹或轻噪点，避免纯色矢量像数字贴纸。

### 6. 创建 Remotion 工程

若没有工程，使用当前 Remotion 创建流程；若环境提供 `remotion:remotion-best-practices`，先读取其 create、markup、captions 和 render 指引。地图场景再额外读取 maps 指引。

把素材放入 `public/`，可编辑组件放入 `src/`。优先拆成：

```text
PaperBackground
CameraMove
PaperLayerReveal
LineDraw
FlowMarks
InfoLabel
CutoutSubject
EvidenceFrame
CaptionLayer
AudioTimeline
```

地图项目可以在此基础上增加 `RegionBand`、`RouteDraw` 和 `MapLabel`。使用 Zod props 暴露标题、配色、素材、位置、入场帧和字幕文件，使模板可重复使用。

### 7. 实现动画

用 `useCurrentFrame()`、`useVideoConfig()`、`interpolate()` 和 `Easing` 驱动全部动作。缩放使用 perceptual scale。可编辑元素使用清晰名称和内联样式。

按以下顺序构建并逐项预览：

1. 静态构图与安全区；
2. 早期 1%–6% 缓慢推镜；
3. 纸片、区域或证据层揭示；
4. 关系线、路线或时间线绘制；
5. 方向标记、标签和图标淡入；
6. 剪纸主体错峰弹入并保持轻微漂浮；
7. 字幕与声音。

实现这些动作前完整阅读 [remotion-patterns.md](references/remotion-patterns.md)。

### 8. 字幕与声音

- 使用 `@remotion/captions` 的 `Caption` JSON；字幕逻辑独立成组件。
- 默认字幕位于底部安全区，白色粗体、深色阴影；不得挡住证据、标签、路径或主体。
- 旁白决定镜头时长。独立音频首尾约 30ms 淡化。
- 纸片揭示用柔和 whoosh，连线完成用轻 impact，主体弹入用 pop/tick；不得盖过旁白。
- 社交平台口播可将约 -16 LUFS 作为起点，再根据平台和素材调整。

### 9. 预览和渲染

先启动 Studio，不自动打开系统浏览器：

```bash
npx remotion studio --no-open
```

先渲染代表帧和低成本样片。只有用户要求成片时再执行正式渲染：

```bash
npx remotion render
```

### 10. 验收

完整执行 [quality-gates.md](references/quality-gates.md)。至少检查：

- 事实性结构、方向、时间和标签是否正确；
- 纸片或色带是否按叙事方向揭示，而非无意义整层淡入；
- 线条、路径或流动标记是否连续、无跳变；
- 剪纸白边、阴影和材质是否统一；
- 字幕、标签、证据和主体是否互相遮挡；
- 开头、结尾和每个关键动作前后是否有黑帧、绿帧或闪动；
- 旁白、字幕和音效是否逐帧对齐；
- 输出参数、响度、校验值和素材来源是否记录。

## 交付

交付时提供：

- 当前推荐视频或样片路径；
- 可编辑 Remotion 工程路径；
- 生产文档和 motion-spec；
- 原始素材与派生素材位置；
- 代表帧/转场验收图；
- 媒体参数、响度和校验值；
- 仍存在的 `PLACEHOLDER`、版权限制或事实不确定性。

需要人类可读的完整生产规范时，读取 [production-blueprint.md](references/production-blueprint.md)。
